# Verify a release artifact, not only a worktree

- Package only tracked source plus explicitly scoped untracked changes and built assets; exclude real `.env`, dependency contents, sessions, cache payloads, database/dumps, private keys and fixture credentials. Include empty writable/runtime directories where read-only bind mounts require mountpoints.
- Store a SHA-256 manifest for every source file and verify both tar contents and safe extraction. Reject absolute/traversal paths, links and device entries. A successful tar operation is not proof of safe or complete packaging.
- Run the existing full suite from the extracted artifact at the Composer application path (`/app` here), using disposable vendor/storage/cache and network-isolated SQLite `:memory:`. Preserve true process exit status; don't infer it from a filtered log. Strip ANSI control sequences before parsing test summaries.
- Record target-engine skipped tests separately. Execute the corresponding MariaDB checks in a guarded disposable database; never weaken memory-only guards to point financial tests at live data.
- If final edits affect documentation only, compare the old tested manifest against the new one. Reuse test evidence only when runtime, migration, view, config, dependency and test hashes are identical; repackage and verify every file. Record that independent QC refers to the earlier hash and the parent verified the exact documentation delta. Never imply the reviewer checked an unreviewed final hash.
- Generate screenshot reports only from the real candidate route with neutral synthetic data. Recheck PDF text and render page images for layout; state that public production password login is distinct from candidate-session verification.
- For private synthetic Laravel session fixtures, save the actual session returned by `Auth::guard('web')->getSession()` after login. A separately resolved session driver can persist a different session and yield a valid encrypted cookie without an authenticated identity. Guard fixture execution by environment and exact disposable DB identity; never add a browser-login bypass route to application source.
- Treat "candidate ready", "deployed" and "production verified" as separate states. A candidate package may document deliberate limits, but must not claim omitted requirements are finished. Cutover needs frozen writes, fresh cutoff backup/restore evidence, explicit existing user roles, source-drift review and public readback. After V2 transactions begin, flag rollback alone is not safe because legacy subledgers differ.
- Avoid broad repeated child assignments at release closeout. Use tiny artifact-specific QC contracts; synchronous delegation can block progress communication. Don't change global Hermes concurrency settings merely to finish an application release.
