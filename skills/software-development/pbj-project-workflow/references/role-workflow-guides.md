# Panduan visual alur peran PBJ

- Untuk PDF alur role, Bagas memilih diagram sederhana, langsung ke poin: satu halaman per role, alur masukan → tindakan → hasil → penerima. Pakai node pendek dan pindahkan detail teknis ke indeks, bukan paragraf panjang.
- Sepakati basis melalui wawancara satu pertanyaan per tahap: perilaku aktual kode atau SOP ideal, kedalaman, dan pelaku luar. Jangan menganggap role data seperti DRIVER otomatis memiliki portal; ketiadaan menu juga bukan bukti pembuatan akun/login mustahil.
- Bekukan commit, lalu bandingkan route, middleware global, controller, dan tombol UI. Periksa izin efektif sebagai irisan, bukan gabungan: pengecualian Super Admin di controller tidak memberi akses jika middleware memblokirnya. Pisahkan izin mengubah status, menyetujui, dan mencetak; terpenuhinya syarat status cetak tidak memberikan role pemanggil hak cetak.
- Untuk setiap perpindahan status penting, telusuri semua jalur penulisnya—persetujuan resmi, status cepat, edit, impor, dan sinkronisasi—lalu bandingkan prasyarat serta efeknya. Tombol approval yang benar tidak melindungi endpoint lain yang langsung menulis status sama; bandingkan jalur resmi dan alternatif pada dokumen sintetis setara, termasuk kuota, kolom persetujuan, dan saldo terkait.
- Pisahkan cabang tujuan dengan percabangan nyata; jangan menggambar toko → gudang sebagai urutan wajib. Panah antar-orang adalah serah-terima konseptual kecuali ada notifikasi otomatis yang terbukti.
- Bedakan status bisnis: siap_cair bukan sudah_dibayar; selesai SPK bukan otomatis truk siap_jalan; faktur bukan bukti penerimaan; rilisan/DO bukan pelunasan hutang. Cocokkan ringkasan reviewer dengan mutasi kode sebelum menggambar.
- Catat perbedaan matriks UI/backend sebagai kekurangan terpisah, bukan kewenangan baru. Inspeksi statis tidak membuktikan request HTTP pasti berhasil; hindari klaim semua tombol terkunci tanpa memeriksa pemakaian helper pada view aktual.
- Gunakan font lokal, diagram SVG, dan render Chromium A4. Validasi seluruh role unik sesuai registry, batas node, jumlah halaman, teks PDF, isi di atas footer, lalu periksa raster PDF. Pendekkan catatan sebelum mengecilkan teks; jangan mengulang warning teknis panjang di tiap role.
- Saat menerima hasil async lama, verifikasi versi/hash dan artefak sebelum menggabungkannya. Jangan mengubah aplikasi, hak akses, data, atau deploy hanya untuk menyusun panduan.
