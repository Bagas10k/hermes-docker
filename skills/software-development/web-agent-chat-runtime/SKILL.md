# Web Agent Chat Runtime & Interface Architecture

Architect and implement robust, bidirectional web chat interfaces and prompt studio environments for autonomous AI agents.

## When to Use
- Building, polishing, or debugging web-based chat interfaces (SaaS dashboards, internal tools, companion HUDs) that interact with AI agents.
- Designing prompt builder/crafter tools integrated directly into an active chat canvas.
- Integrating external chat bridges (e.g. Telegram parity, WhatsApp, Discord) with local web interfaces without causing identity collisions or loop deadlocks.

## Architecture & Turn Lifecycle

```
[Web Chat Frontend]
       │
       ▼ (POST /api/.../chat { message, agent })
[Backend Bridge / Route]
       │
       ├──> 1. Record User Turn: { role: 'user', sender: '<User Name>', content }
       ├──> 2. Query Model Endpoint: POST /v1/chat/completions (9router / local LLM)
       │       with Persona & Constraints Context
       ├──> 3. Record Assistant Turn: { role: 'assistant', sender: '<Agent Name>', content }
       │
       ▼ (Response { ok: true, userMessage, assistantMessage })
[Web Chat Frontend] ──> Resolves thinking indicator, renders markdown & code blocks
```

## Procedure

1. **Establish State Persistence & Message Schema**:
   Define a unified message contract before building UI:
   `{ id: number, role: 'user' | 'assistant', sender: string, content: string, time: string, metadata?: object }`.
   Store history in a local SQLite table or persistent state file (`~/.local/state/<app>/chat_history.json`).

2. **Decouple Inbound User Turns from Outbound Bot Tools**:
   - For web prompt submissions, dispatch the message directly to the completions/agent execution endpoint as `role: 'user'`.
   - Never invoke outbound bot broadcast tools (e.g. `hermes send --to <target>`) with the raw user prompt. If external channels require mirroring, format explicitly with sender attribution: `[Web Studio] <User>: <prompt>\n<Agent>: <reply>`.

3. **Implement Floating Prompt Dock & Anti-Bleed Layout**:
   - Position floating dock capsules with backdrop blur and high-opacity gradient backing (`linear-gradient(180deg, rgba(..., 0) 0%, rgba(..., 0.85) 15%, #... 40%, #... 100%)`).
   - Calculate container bottom padding strictly exceeding dock height plus gradient threshold: `padding-bottom: calc(var(--dock-height) + 40px);`. This prevents bottom chat bubbles from bleeding behind interactive chips or input textareas.

4. **Zen Minimalist Canvas & Major LLM Parity (ChatGPT & Claude Standards)**:
   - **Zero-Slop Empty State**: Keep the empty state clean, calm, and uncluttered. Forbid sprawling multi-paragraph prompt template cards, tag buttons, and bloated in-canvas prompt crafters unless explicitly requested. Users favor a serene, minimal greeting (e.g. "Ada yang bisa Mumu bantu?", "Model bk aktif • Siap mendampingi") with expansive whitespace.
   - **Zero Emoji Doctrine (Apple SF Symbols Standard)**: Forbid Unicode emojis (`✨`, `🐴`, `●`, `✦`, `👍`, `👎`, `⏱`) across the entire UI, including titles, brand labels, action buttons, toasts, and status pills. Use only crisp, minimalist line-based SVG vector glyphs modeled after Apple's SF Symbols.
   - **In-Dock Agent & Thinking Effort Selectors Alongside Execution Button (ChatGPT & Claude Paradigm)**: Never hide model selection in distant top headers or stack them clumsily in separate bars. Mount controls in a streamlined two-tier dock:
     - **Top Tier**: Expanding auto-growing textarea (`.dock-input-row`).
     - **Bottom Action Tier (`.dock-action-bar`)**: Attachment button on the far left; on the far right, position the Model Picker Pill (`[Mumu bk ▾]`), Thinking Effort Pill (`[Think: Standar ▾]`), and the Execution (Send) Button sitting directly alongside each other.
     - **Pill Button Styling (Frosted White Glass Blur)**: Style pills with translucent frosted white glass blur (`background: rgba(255, 255, 255, 0.76); backdrop-filter: blur(16px); border: 0.5px solid rgba(255, 255, 255, 0.95); color: #1e293b; box-shadow: 0 2px 8px rgba(14, 27, 49, 0.04); border-radius: 9999px;`).
     - **Execution Button (Luminous Blue Gradient)**: Style the send button with a vibrant blue gradient (`background: linear-gradient(135deg, #2b7fff 0%, #0059f7 50%, #0047d4 100%); color: #ffffff; box-shadow: 0 4px 14px rgba(0, 89, 247, 0.32);`).
   - **Dynamic Send / Stop Generation Toggle**: While the AI is generating or streaming, morph the send button (`↑`) into a high-contrast stop button (`■`) wired to `AbortController.abort()` to give users instant cancellation control.
   - **Auto-Expanding Upward Textarea with Continuous Squircles**: Style the input capsule with continuous Apple squircle curves (`border-radius: 24px-26px`). As multi-line prompts are typed, the textarea expands upwards smoothly (`transition: height 0.18s cubic-bezier(0.16, 1, 0.3, 1)`) up to a 140px ceiling with a hidden scrollbar.
   - **Mobile Virtual Keyboard Pinning (`window.visualViewport`)**: Handle mobile software keyboards reliably. Bind both `resize` and `scroll` events on `window.visualViewport` to dynamically calculate `offsetFromBottom = window.innerHeight - (visualViewport.height + visualViewport.offsetTop)`. When the virtual keyboard pops up, pin `dock.style.bottom = `${offsetFromBottom + 10}px`` so the input dock sits cleanly 10px above the keyboard rather than getting submerged or floating mid-screen. Pair with `interactive-widget=resizes-content` in the viewport meta tag.
   - **User Prompt Bubble Sizing & Harmonious Light Blue Gradient**: Size user prompt bubbles strictly to hug prompt content (`width: fit-content; max-width: 82%; margin-left: auto;`) rather than stretching full width. Style with a harmonious light sky-blue pastel gradient (`background: linear-gradient(135deg, #e0f2fe 0%, #bae6fd 50%, #93c5fd 100%);`) paired with deep navy typography (`color: #032b56; font-weight: 600;`), specular highlight rim, and squircle corner radii (`border-radius: 18px 18px 4px 18px`).
   - **Cardless / Unboxed Assistant Editorial Presentation (No Bubble)**: Never enclose assistant responses in rounded cards, borders, or bubble containers on light canvas UIs. Present responses as free-flowing unboxed editorial text directly on the canvas (like Claude and ChatGPT web clients). Enforce high-standard typography:
     - Paragraphs with comfortable vertical rhythm (`margin-bottom: 12px; line-height: 1.7; color: #0f172a;`).
     - Preserved single line breaks (`<br>`) and double-break paragraphs.
     - Sequential ordered numbered steps ("perurutan / tangga": `<ol><li>...</li></ol>`).
     - Clean unordered bullet lists (`<ul><li>...</li></ul>`).
     - Duplex comparison tables (`<table>` with subtle hairline dividers and tinted headers).
     - Bold (`<strong>`) and italic (`<em>`) hierarchies.
     - Dark syntax code blocks with copy affordance.
     - Underneath utility toolbar: Salin, Buat Ulang, and transparent Token & Biaya badge.
   - **Dual-Edge Scroll Opacity Gradient Mask (Top Mascot & Bottom Dock Fading)**: Apply a dual-edge vertical gradient mask to the scrollable chat feed (`-webkit-mask-image: linear-gradient(to bottom, transparent 0px, black 36px, black calc(100% - 90px), transparent 100%); mask-image: linear-gradient(...)`). Messages scrolling up dissolve into opacity 0 before touching the mascot/header boundary, and messages scrolling down dissolve seamlessly into opacity 0 beneath the floating input prompt dock, eliminating all hard clipping seams.
   - Fenced Code Blocks with macOS Window Header & Syntax Highlighting: Never render code blocks as flat monochromatic black boxes in light-mode iOS interfaces. Style code blocks with an Apple macOS Terminal window aesthetic:
   - Header: Frosted translucent glass (`background: rgba(255, 255, 255, 0.75); backdrop-filter: blur(14px)`), macOS three-dot window controls (red `#ff5f56`, yellow `#ffbd2e`, green `#27c93f`), uppercase monospace language tag in ocean blue (`#0369a1`), interactive live preview button for web code (`[Pratinjau]`), instant file download button (`[Unduh File]`), and an interactive copy button with animated emerald checkmark (`#34d399`) and audio chime.
   - Body: Soft pastel light-blue gradient background (`linear-gradient(145deg, #f0f7ff 0%, #e0f2fe 50%, #d6ebfd 100%)`) with a delicate hairline border (`1px solid rgba(147, 197, 253, 0.7)`), inset white specular highlight, and soft ambient drop shadow (`box-shadow: 0 6px 18px rgba(56, 189, 248, 0.12)`).
   - Colorful Syntax Highlighting: High-contrast, vibrant syntax tokens against the light-blue canvas across both programming code and markup (HTML, SVG, XML, CSS):
     - Tags (`<html>`, `<head>`, `<div>`, `<svg>`): Bold Royal Indigo / Purple (`#4f46e5`).
     - Attributes (`class`, `id`, `src`, `href`): Vivid Azure / Cobalt (`#0284c7`).
     - Keywords (`const`, `function`, `return`, `if`, `await`): Bold Royal Indigo / Purple (`#4f46e5`).
     - Strings (`"..."`, `'...'`, `` `...` ``): Deep Emerald Green (`#047857`).
     - Numbers & Literals (`0`, `0.95`, `42`): Warm Amber / Tangerine (`#ea580c`).
     - Comments (`// ...`, `# ...`, `<!-- ... -->`, `<!DOCTYPE>`): Muted Slate-Blue Italic (`#64748b`).
     - Base Code Text: Deep Navy (`#0f2b48`) for effortless readability.
   - Scoped Inline Code Selectors: Strictly target inline code using `.message-bubble :not(pre) > code` with subtle sky-blue gradient (`linear-gradient(135deg, #f0f9ff 0%, #e0f2fe 100%)`), and explicitly reset `.code-block-wrapper pre code { background: transparent !important; border: none !important; padding: 0 !important; color: #0f2b48 !important; }` to prevent nested inline-code background highlights from bleeding behind code lines.
   - **Interactive Live Preview Sandbox (Claude Artifacts / ChatGPT Canvas Paradigm)**: For web code blocks (HTML, SVG, XML), equip the code header with an interactive `Pratinjau` button that launches a frosted glass modal sandbox (`#modal-artifact-preview`). Render the code via an `<iframe>` with `sandbox="allow-scripts allow-modals"` and `srcdoc`. Equip the modal with macOS window dots, device viewport toggle (Mobile 390px vs Desktop 100%), open in new tab affordance, and close button. On mobile screens ($\le 600\text{px}$), wrap button labels in `<span>` and hide them (`display: none;`) to keep touch targets icon-only and prevent header title vertical wrapping.
   - **1-Click File Export & Disk Persistence**: Mount an `[Unduh File]` button alongside copy controls on every code block. Dynamically map language tags to filenames (`html` $\to$ `landing-page.html`, `js` $\to$ `script.js`, `py` $\to$ `script.py`, `css` $\to$ `styles.css`, `json` $\to$ `data.json`, `csv` $\to$ `table.csv`, `sql` $\to$ `query.sql`, `sh` $\to$ `run.sh`, `svg` $\to$ `diagram.svg`). Generate client-side Blob downloads (`URL.createObjectURL(new Blob([code], { type: mime }))`) with haptic feedback. Pair with backend endpoints (`POST /api/.../save-file`) for optional server-side disk writes.
   - **Multimodal Image Cards & Lightbox Modal**: Parse markdown image syntax `![alt](url)` into a dedicated rounded frosted card (`.chat-image-card`) with loading placeholder, click-to-expand lightbox modal (`#modal-image-lightbox`), caption label, and instant download button. Avoid class names containing `card`, `box`, `panel`, `tile` for image viewer wrappers (e.g. use `.image-viewer-stage`) to prevent automated layout linters from misidentifying empty media containers as abandoned decorative text cards (`EMPTY_DECORATIVE_SLOP`).
   - **Silent In-Dock Pill Feedback (Anti-Toast Clutter)**: When users toggle model or reasoning effort selectors in the input dock, update the pill text label directly (`#label-dock-model`, `#label-dock-thinking`) accompanied by an acoustic tick or micro-haptic. Never fire floating toast notifications (`toast("Penalaran: Think: Off")`) for routine dropdown selections; they add visual noise, distract the user, and collide with the character mascot's visor.
   - **Empty Zen State Fast Suggestions**: Beneath the minimal greeting headline, provide 3 compact, frosted quick-action suggestion chips (`.suggestion-chip`, `border-radius: 9999px; background: rgba(255, 255, 255, 0.75); backdrop-filter: blur(14px); border: 0.5px solid rgba(255, 255, 255, 0.95); font-size: 12px; font-weight: 600; color: #1e293b;`). Clicking a chip instantly fills the input and triggers execution, eliminating friction for new sessions.
   - **Floating Jump-to-Bottom Scroll Affordance**: Mount a floating circular button (`#btn-scroll-bottom`, `36px × 36px`, frosted white blur, down chevron icon) positioned above the dock. Listen to chat stream scroll events and reveal it with smooth fade-in whenever the user is scrolled up $> 160\text{px}$ from the bottom, snapping back down on click with `behavior: 'smooth'`.
   - **Table Containment Wrapping (`.table-wrap`)**: Always wrap parsed markdown tables in an independent overflow container (`.table-wrap`, `width: 100%; overflow-x: auto; -webkit-overflow-scrolling: touch; border-radius: 12px; border: 0.5px solid rgba(14, 27, 49, 0.1); box-shadow: 0 2px 8px rgba(14, 27, 49, 0.03);`) to isolate wide multi-column tables and prevent horizontal layout disruption on mobile.
   - **Critically Damped Mascot Kinematics (Anti-Jitter & GPU Promotion)**: Never attach `transition: transform` in CSS to elements whose transforms are animated every frame via JavaScript `requestAnimationFrame`. Simultaneous CSS cubic-bezier transition interpolation fights the 60 FPS JS solver on every frame, generating violent high-frequency jitter (*getar hebat*). Use critically damped spring physics ($k \approx 0.08, c \approx 0.74$, resting dead-zone clamp $< 0.0015$, gentle impulse $-0.14$), promote to GPU compositing layers (`will-change: transform; transform: translateZ(0); -webkit-backface-visibility: hidden; backface-visibility: hidden;`), and keep the outer container card stationary during taps.
   - **Assistant Message Action Toolbar & Transparent Token Cost Metric**: Attach a clean utility toolbar directly below each assistant response containing "Salin" (copy text), "Buat Ulang" (regenerate response), and a transparent token cost badge (e.g. `45 token • Biaya: $0.0001`) with tooltip clarification to prevent users from mistaking API compute tokens for word/sentence counts.
   - **Silky Smooth Text Reveal Animation**: In streaming responses, animate text smoothly with a micro vertical glide and blur fade (`@keyframes iosTextReveal { from { opacity: 0; transform: translateY(8px); filter: blur(2px); } to { opacity: 1; transform: translateY(0); filter: blur(0); } }`) for a calm, editorial feel.
   - **Compact Settings Popover Dropdown (Anti-Full-Screen Modal)**: Forbid intrusive full-screen settings modals. Mount an elegant top-right floating iOS popover (`width: ~280px-300px`) beneath the settings gear with horizontal sliding submenus (`‹ Kembali`):
     - **Main View**: Quick toggles (Sound effects switch, Haptic touch switch) and navigation links to submenus.
     - **Instruksi Kustom Submenu**: Dual-textarea paradigm: "Tentang Anda / Proyek" and "Gaya & Batasan Respon".
     - **Model & Parameter Submenu**: Temperature slider (`0.0` deterministic to `1.0` creative), reasoning framework toggle, and Obsidian Vault status.
     - **Skedul Otomasi (Scheduler) Submenu**: Display active background cron/automation jobs fetched from `/api/.../cron` (e.g. `jobs.json`) with intervals and execution status badges (`Aktif` / `Jeda`).
     - **Hapus Riwayat Chat**: Red destructive action at the base of the main menu.
   - **Slide-Over Chat History Drawer**: Provide a left-hand frosted glass drawer (`width: ~310px`) triggered by a top-left clock/history icon for browsing, resuming, and deleting past conversation sessions stored in `localStorage`.
   - **Continuous Liquid Opacity Gradient Masks (No Harsh Cutoffs)**: Avoid harsh horizontal blur cuts. Use `-webkit-mask-image: linear-gradient(to bottom, black 70%, transparent 100%)` for sticky headers and `linear-gradient(to top, ...)` for bottom docks so blurs feather seamlessly into the canvas.
   - **Harmonious Multi-Stop Blue Gradient User Bubble (Apple iOS iMessage Standard)**: Forbid flat dark navy or dull slate fills for user prompt bubbles on light-mode or pastel canvases. Style user prompt bubbles with a luminous, seamless multi-stop blue gradient (`linear-gradient(135deg, #3b82f6 0%, #2563eb 32%, #1d4ed8 68%, #1e40af 100%)`), specular top rim highlight (`inset 0 1px 1.5px rgba(255, 255, 255, 0.5)`), hairline border (`0.5px solid rgba(255, 255, 255, 0.35)`), colored diffuse ambient glow (`box-shadow: 0 6px 20px rgba(37, 99, 235, 0.28)`), and an asymmetrical squircle corner radius (`border-radius: 20px 20px 4px 20px`) anchoring the lower-right edge to the sender.
   - **Code Economy & Anti-Sprawl Architecture**: Consolidate CSS with semantic variables, eliminate dead preset text blobs and abandoned modal DOM, and keep single-file web UIs under clean, modular bounds (~1,000–1,500 lines) instead of sprawling into bloated 4,000-line monolithic files.

5. **Format Markdown, Numbered Lists & Paragraphs Safely**:
   - Stash fenced code blocks (` ``` `) with placeholder tokens (`@@CODEBLOCK_n@@`) before text parsing to preserve indentation, newlines, hashes, and symbols intact.
   - Tokenize numbered lists (`1. `, `2. `, `1) `, `a. `) and bullet lists (`- `, `* `, `• `) into semantic `<ol class="md-numbered-list">` and `<ul class="md-bullet-list">` with `<li>` tags. Accumulate continuation lines and indented paragraphs into the active list item rather than breaking the list prematurely.
   - Style list markers with accent color and monospace numerals (`ol li::marker { color: var(--accent-terracotta); font-weight: 700; font-family: var(--font-mono); }`) for clear visual rhythm.
   - Split remaining text by double newlines (`\n\n+`) into distinct paragraphs (`<p>` with `margin-bottom: 12px; line-height: 1.65;`). Convert single newlines (`\n`) inside paragraphs into `<br>`.
   - Block element containment: Never wrap block-level tags (`<h1>`-`<h6>`, `<ol>`, `<ul>`, `<pre>`, `<hr>`, `<blockquote>`) in `<p>` tags; browser parsers auto-close `<p>` on block elements, causing malformed DOM trees and broken spacing.
   - Transform markdown links `[text](url)` to styled anchors with `target="_blank"` and `rel="noopener"`.
   - Markdown Pipe Tables (`| ... |`): Parse pipe-delimited markdown tables into responsive HTML tables (`<table class="md-table">`) wrapped in an overflow container (`overflow-x: auto;`) with alternating zebra striping and tinted headers (`rgba(0, 229, 255, 0.08)`). Do not leave raw markdown table syntax (`|:---|:---|`) unrendered as plain text.
   - Restore code blocks into `<pre><code class="language-...">` containers after paragraph and list assembly.

6. **Mobile-First Ergonomics & Viewport Confinement**:
   - Lock outer viewport to `100dvh`: Set `html, body { height: 100%; height: 100dvh; overflow: hidden; position: fixed; inset: 0; width: 100vw; max-width: 100vw; }` to eliminate mobile browser URL-bar jump and rubber-band elastic bouncing.
   - Header responsive adaptation: On viewports $\le 640\text{px}$, hide verbose subtitles, condense action labels to icon-only buttons with $\ge 36\text{px}$ to $44\text{px}$ touch targets, and ensure `header.scrollWidth === header.offsetWidth` (zero horizontal overflow).
   - Mobile Full-Bleed Expansive Chat Column ("Anti-Kolom Sempit di Mobile"): Never retain desktop inset card margins (`left: 8px-16px; right: 8px-16px;`) on mobile ($\le 768\text{px}$). Enforce edge-to-edge containerization (`left: 0; right: 0; border-left: none; border-right: none; border-radius: 24px-28px 24px-28px 0 0;`) with streamlined padding (`padding: 8px 12px 145px;`). This expands readable width to 92%–95% of screen width (~366px on standard 390px phones) instead of squeezing text into a narrow 300px column. In assistant messages on mobile, stack the avatar above the text or use an inline name tag (`flex-direction: column; gap: 4px;`) so the text block receives 100% horizontal width rather than losing 36px–40px to an avatar column on every line.
   - Generous Mobile Input Field Tap Target: Never restrict mobile chat textareas to a tiny 22px–26px slit. Enforce `min-height: 38px-42px; font-size: 15px; line-height: 1.45;` with continuous squircle corners (`border-radius: 22px`). Setting `font-size: 15px` prevents intrusive iOS auto-zooming on focus while providing a generous, accessible touch target. Clear device navigation bars using `bottom: max(8px, env(safe-area-inset-bottom, 8px));`.
   - Asymmetric messenger bubble ergonomics: Align user bubbles to the right (`align-self: flex-end`) with rounded corners on three edges and a tight lower corner (`border-radius: 18px 18px 4px 18px`), high-contrast dark fill (Midnight Navy), and crisp white text. Align assistant bubbles to the left (`align-self: flex-start`, `border-radius: 18px 18px 18px 4px`) with frosted glass crystalline backing, anchored by a distinct companion avatar. Cap bubble wrapper max-width at `82%-86%` on mobile so bubbles never collide with screen edges. Suppress redundant user sender names above short user messages to eliminate awkward layout gaps; rely on right alignment, initial avatar, and subtle timestamps.
   - Silk Fade Scroll Masking: Apply a subtle vertical gradient mask to the scroll container (`-webkit-mask-image: linear-gradient(to bottom, transparent 0px, black 14px, black calc(100% - 20px), transparent 100%); mask-image: linear-gradient(...)`) so older messages scrolling under sticky headers or sibling companion bars dissolve smoothly into the background rather than clipping harshly across a sharp boundary.
   - Input capsule auto-expansion: Avoid multi-line placeholder wrapping by using concise single-line placeholders with `white-space: nowrap; overflow: hidden; text-overflow: ellipsis;`. Keep textarea at single-line height (`22px`), auto-expand up to `120px-140px` on input, and reset to `22px` on submit.
   - Bottom-sheet modal transformation: Morph centered desktop modals into mobile bottom sheets (`border-radius: 22px 22px 0 0; max-height: 90dvh; display: flex; flex-direction: column;`), provide a centered top drag bar (`.modal-drag-bar`), sticky full-width primary CTA footer, and multi-line textareas for constraint fields.
   - Chip toolbar end clearance: Add `padding-right: 20px-24px` to horizontally scrollable chip bars so the rightmost chip does not collide with the mobile screen bezel.
   - 2×2 Grid vs Horizontal Carousel for Welcome Cards: While horizontal swipe carousels work in full-bleed mobile contexts, inside container cards (~375px wide) they often truncate cards off-screen with poor swipe affordance. Format welcome prompt cards into a clean 2×2 grid (`grid-template-columns: 1fr 1fr; gap: 8px;`) with 2-line clamped descriptions so all 4 core prompts remain immediately visible and actionable without any scrolling.

7. **Manage Non-Blocking Asynchronous UI Lifecycle**:
   - When the user sends a prompt, render the user bubble immediately and insert an animated thinking indicator on the assistant side.
   - Dispatch the HTTP request asynchronously. Decouple synchronous browser evaluation from LLM latency to prevent IPC timeouts.
   - On completion, replace the thinking indicator with the parsed assistant response and trigger smooth auto-scroll to the bottom.

8. **Zero-Asset Synthesized Sensory Feedback (Web Audio & Haptics)**:
   - Synthesize auditory and physical confirmation via Web Audio API oscillators and `navigator.vibrate` without relying on heavy external sound files:
     - Prompt dispatch: Airy whoosh ($340\text{Hz} \to 620\text{Hz}$, 120ms) + single tap haptic (`[15]` ms).
     - Assistant reply arrival: Crystalline double-tone chime ($740\text{Hz} \to 932\text{Hz}$, 320ms) + success double vibration (`[18, 45, 24]` ms).
     - Companion mascot tap / reaction: Playful spring pop ($460\text{Hz} \to 780\text{Hz}$, 160ms) + elastomeric snap vibration (`[12, 25, 20]` ms).
   - Wrap audio/haptic calls in non-blocking error guards (`try/catch`) and ensure `audioCtx.resume()` is evaluated inside user gesture listeners to comply with browser autoplay policies.

9. **Deterministic Dirty-Checked Polling (Anti-Flicker Sync)**:
   - When polling background messages via `setInterval`, never execute destructive `container.innerHTML = renderedHtml` on every tick.
   - Compute a lightweight deterministic signature before touching the DOM:
     ```javascript
     function computeChatSignature(messages) {
       if (!messages || messages.length === 0) return 'empty';
       const last = messages[messages.length - 1];
       return `${messages.length}:${last.time || ''}:${(last.content || '').length}`;
     }
     ```
   - Only execute DOM re-renders if `computeChatSignature(messages) !== lastRenderedSignature`.
   - Gate polling by tab visibility (`document.hidden`) and ongoing request states (`isWaitingForResponse`) to eliminate unnecessary CPU/network churn.

10. **Persistent Living Companion & Corner Mascot Doctrine**:
    - Decouple character / mascot stages from ephemeral welcome screens or prompt cards.
    - Position the companion as a structural sibling *outside* the message scroll stream (`<main> > #companion-zone + #chat-stream`):
      - **Idle / Hero Mode**: Full-sized interactive 3D/2D mascot centered on screen with welcome headline and preset cards below.
      - **Active Chat Mode**: When messages exist, smoothly fold away only the welcome headline and preset cards. Station the mascot prominently in the corner (e.g. top-left corner) as a large, expressive, tactile character (~78px-86px stage, scale ~0.68-0.74). Do NOT compress it into a tiny, illegible 32px icon badge.
      - **Transparent Ambient Gradient**: Anchor the corner mascot with a soft atmospheric radial or elliptical gradient (`radial-gradient(ellipse 240px 95px at 45px 50%, rgba(..., 0.96) 0%, rgba(..., 0.72) 42%, rgba(..., 0) 100%)`) that fades seamlessly into 100% transparency towards the side and bottom. Forbid hard border lines or bottom divider cuts (`border: none !important; border-bottom: none !important;`).
      - **Omit Side Status Text**: Completely hide/remove explanatory text pills beside the mascot during active chat (`.status-pill { display: none !important; }`). Let the mascot's eyes (tracking, blinking, pulsing thinking, smiling curves) and vocal sound cues communicate its state. This eliminates visual clutter and grants maximum vertical/horizontal breathing room to the chat feed.
      - **Headroom Clearance & Downward Bias ("Anti-Molor ke Atas")**: When enlarging the mascot in the corner, scaling from center pushes upper geometry (antenna, ears, head dome) upwards. Apply a downward vertical bias offset in kinematics (`chatOffsetY >= 8px-12px`) and damp the idle breathing float amplitude (e.g. from $\pm 7\text{px}$ to $\pm 1.6\text{px}$) so the apex never creeps into the sticky header boundary. Ensure clean positive clearance (`rigTop - headerBottom >= 6px-10px`).
    - Kinematics-to-CSS Scale Synchronization: When animating the mascot via `requestAnimationFrame` with inline `transform: translate3d(...) scale(...)`, the JS loop overwrites CSS class rules (`.chat-mode { transform: scale(...) }`) every tick. Manage the base scaling factor inside the JS kinematics engine based on state query (`isChatMode ? (isMobile ? 0.70 : 0.74) : 1.0`), so the mascot remains proportionally large and expressive without clipping headers.
    - Anti-Elongation Proportions ("Anti-Lonjong"): Never design mascot dimensions taller than they are wide (e.g. 118px width by 142px height with egg-shaped radii), and never bias harmonic breathing vertically ($scale_y$ expanding while $scale_x$ contracts). An elongated egg silhouette feels stiff, alien, and "lonjong". Maintain chubby, plump squircle geometry (width >= height, e.g. 136px by 124px, with 46%–50% curvature radii) and lateral breathing bias ($scale_x = 1.0 + \sin(t \times 2.0) \times 0.018$) so the mascot looks cuddly, friendly, and living.
    - Keep eye animations, blushing, spring physics, and sound reactions fully functional during active chat so the mascot accompanies the conversation without scrolling out of view or occluding messages.

11. **Explicit Session Reset & "New Chat" Action**:
    - Place an unambiguous, high-contrast `+ Chat Baru` / `+ New Chat` capsule button in the primary navigation header (never hide it behind an obscure trash icon or nested submenu).
    - On click, execute an atomic reset sequence:
      1. Dispatch `POST /api/.../clear-chat` to reset backend state.
      2. Clear the message container and reset `lastRenderedSignature = 'empty'`.
      3. Transition the companion container back to `hero-mode` with elastic spring motion.
      4. Play the authentic greeting audio cue (`greet.wav`) and trigger haptic feedback.
      5. Display an instant feedback toast notification confirming the new session.

12. **Pre-Decoded Authentic Audio Buffers with Synthetic Fallback**:
    - For rich character audio (e.g. 28 WAV files for clicks, greetings, thinking, completions), pre-fetch and decode them into memory `AudioBuffer` objects via `audioCtx.decodeAudioData` upon initial user interaction for true 0ms latency.
    - Maintain a lightweight Web Audio oscillator generator as an automatic fallback if audio files fail to load or are blocked by browser media policies.

    - **Headroom Clearance Invariant ("Anti-Terlalu ke Atas")**: Never pin container `top` directly beneath the top navbar (e.g. `top: 50px` under a 52px navbar). Enforce container `top: 80px-86px` on mobile (desktop `76px`) to ensure $\ge 30\text{px}-34\text{px}$ of open headroom between the top bar and container apex. This places the mascot comfortably in the golden focal zone of the upper screen with unobstructed clearance for unclipped ears and antennae.
    - **Unclipped 3D Appendages (`overflow: visible` Invariant)**: The living body card MUST be set to `overflow: visible;` so that tactile 3D claymorphic ears (`.mumu-head-ear`) and the glowing antenna jewel ball (`.mumu-head-antenna`) can rise unclipped over the top rim into the pastel sky. Model volumetric ears with snug base grounding sockets (`.mumu-ear-socket`), crisp outer rim highlights, and an inset inner sensor conch (`.mumu-head-ear::after`). Endow ears with multi-state living kinetics:

Keep client labels strictly simplified to the core persona identity (`Mumu`) to maintain an elegant, consumer-grade Apple feel.
    - **Stationary Head & Face Anchor (`#hero-mumu-zone`)**: Mounted at the top apex of the container card. Features a frosted translucent background (`backdrop-filter: blur(20px); background: rgba(255, 255, 255, 0.82); z-index: 25;`), sunken obsidian visor with diagonal glass reflection, glowing OLED eyes, and soft peach-rose blushing cheeks (`.mumu-blush`).     - **Independent Inner Scroll Invariant**: Inside the character's body sits `#chat-stream` (`flex: 1; overflow-y: auto; overflow-x: hidden;`). When the user scrolls up or down, **only the chat messages scroll inside—the character's body container, ears, antenna, and face remain 100% stationary** (`containerMoved: false`, `faceMoved: false`).

## Pitfalls

- **Naïve RegEx List Splitting**: Splitting numbered lists with single-line regexes breaks multi-line explanations or indented paragraphs, ejecting the explanation out of the `<ol>` container. Use a tokenizer that accumulates continuation lines into the current list item.
- **Block Elements Inside `<p>`**: Wrapping raw markdown outputs in `<p>` causes browsers to prematurely terminate paragraphs on headers, lists, and code blocks, resulting in malformed DOM trees and collapsed margins.
- **The Bot Echo Trap**: Piping user chat inputs into outbound bot dispatchers (e.g. `hermes send --to telegram`) transmits the prompt under the bot's token credentials. In mirrored channels the prompt arrives as an agent message, and the agent's self-message filter drops it to prevent infinite loops, leaving the prompt unaddressed.
- **Mobile Multi-Line Placeholder Truncation**: Long placeholder text in compact mobile input capsules wraps onto a second line, causing vertical glyph clipping against container borders. Always enforce single-line placeholder styling with `white-space: nowrap; text-overflow: ellipsis;`.
- **The Inset Mobile Container Squeeze Trap ("Kolom Chat Sempit")**: Keeping desktop card margins (`left/right: 8px-16px`) and forcing side-by-side avatar rows on mobile restricts assistant reading width to $<300\text{px}$, creating a cramped receipt-like text column. On mobile ($\le 768\text{px}$), enforce full-bleed containerization (`left: 0; right: 0; border: none;`), stack the avatar above text or use an inline header, and expand the input field tap target to `min-height: 38px-42px; font-size: 15px;`.
- **The Tiny Slit Textarea Tap Target**: Setting mobile chat textareas to single-line 22px-26px heights creates an uncomfortable, cramped tap zone on touchscreens. Enforce `min-height: 38px-42px; font-size: 15px;` with `bottom: max(8px, env(safe-area-inset-bottom, 8px))` to maintain thumb comfort and prevent iOS viewport zoom.
- **Mobile Header Horizontal Overflow**: Retaining multi-word button labels and wide brand subtitles on small viewports inflates header `scrollWidth` past `100vw`, breaking page touch gestures. Collapse labels to icon-only buttons and hide secondary branding under $\le 640\text{px}$.
- **Modal Preview Collision with Sticky Footers**: Sticky action footers in mobile bottom sheets cover the bottom lines of prompt previews or code snippets unless `.modal-body` carries explicit `padding-bottom: calc(var(--footer-height) + env(safe-area-inset-bottom, 0px))`.
- **Gradient Bleed Confusion**: Using transparent gradients across the entire bottom dock allows background message text to show through interactive chip labels, causing visual collision and failing accessibility contrast standards.
- **Synchronous Promise Blocking**: Awaiting long-running LLM generation inside synchronous browser automation wrappers (`Runtime.evaluate` with `awaitPromise=true`) triggers helper IPC timeouts before the model returns. Decouple request execution from the event loop.
- **Untyped Message Roles**: Relying on string heuristic pattern matching instead of explicit `role` fields causes user prompts and agent responses to invert when messages are re-fetched from storage.
- **Full-Width Chat Bubble Bleed**: Allowing chat bubbles to span 100% width on mobile eliminates the visual distinction between sender and receiver. Restrict bubble wrappers to `82%-86%` max-width with opposite horizontal alignment.
- **Unresumed AudioContext Autoplay Failure**: Invoking Web Audio oscillator synthesis before the user's first click or touch event fails silently due to browser autoplay policies. Lazy-initialize or resume `AudioContext` within the pointer/touch handler before triggering tones.
- **Destructive Polling Reflow Loop ("Pseudo-Refresh")**: Blindly overwriting `container.innerHTML` on every polling interval without dirty-checking forces complete DOM teardown and repaint, mimicking an unprompted page reload every few seconds and unfocusing inputs. Always compute and compare a lightweight signature (`${messages.length}:${last.time}:${last.content.length}`) before updating the DOM.
- **The Scroll-Drowned Mascot**: Putting the mascot or companion avatar inside the scrollable message container causes it to scroll out of view when messages expand, creating the illusion that the mascot disappeared upon chatting. Keep companion stages as structural siblings outside the scroll container (`<main> > #companion-zone + #chat-stream`).
- **Kinematics Transform Clobbering (The Exploding Mascot Bug)**: Setting CSS classes like `.chat-mode { transform: scale(0.35); }` fails if a continuous `requestAnimationFrame` JavaScript loop writes `element.style.transform = 'translate3d(...) scale(1.0)'` on every frame. The inline style wins every tick, causing the full-size mascot head to escape small container bounds and occlude header navigation. Always manage base scale within the JS kinematics matrix.
- **Harsh Scroll Clipping at Sticky Boundaries**: Abruptly terminating scroll container bounds directly beneath floating headers causes half-rendered avatars and text lines to visually collide. Use CSS `-webkit-mask-image` linear gradient fading at the top edge of the scroll area.
- **Scroll Fade-Mask Top Inset Collision**: Applying a top linear gradient mask to a scroll container (`-webkit-mask-image: linear-gradient(to bottom, transparent 0px, black 14px, ...)`) clips the top pixels of the first message or card if container `padding-top` $\le$ the fade distance. Always set container `padding-top` strictly greater than the mask fade threshold (e.g. $\ge 20\text{px}$ for a 14px fade mask) so initial messages never start inside the transparent fade boundary.
- **The Shrunken Badge & Cluttered Status Pill Trap**: Compressing the mascot into a 32px badge alongside an explanatory text pill cramps the mobile screen, creates awkward visual competition with message bubbles, and robs the character of its expressive charm. Keep the mascot large in the corner with an ambient transparent gradient and eliminate the side text bar completely.
- **Hard Border Cuts on Ambient Gradients**: Adding 1px bottom or side borders to an ambient companion gradient ruins the illusion of a seamless organic atmosphere and leaves sharp visible seams against the chat stream. Enforce `border: none !important; border-bottom: none !important;`.
- **The Upward Rig Drift ('Molor ke Atas') & Negative Headroom Trap**: Scaling up a centered 3D/CSS mascot in a corner stage expands the character equally upwards and downwards. Without a downward transform offset (`chatOffsetY`) and damped vertical hover amplitude, the mascot's antenna or head apex drifts upwards and collides with or overlaps the top header border (`rigTop < headerBottom`), creating a visually cramped, stretched feeling ("molor ke atas"). Always introduce a downward vertical offset and verify positive headroom clearance ($\ge 6\text{px}-10\text{px}$) against the sticky header.
- **The "Lonjong" Mascot Egg Proportion Pitfall**: Setting mascot container height greater than width with an asymmetric egg-shaped border-radius and vertical harmonic breathing makes the mascot look oblong, rigid, and awkwardly stretched ("terlalu lonjong"). Enforce squircle/chubby dimensions where width >= height (e.g. 136×124px) with symmetric 48%–50% curvature and lateral breathing expansion.
- **The Character Scroll Drift Trap**: In Character-as-Container architectures, letting the outer character body or facial elements scroll along with the chat messages breaks the physical container illusion and causes the mascot's eyes to disappear off the screen. Keep the character card and face strictly pinned (`position: absolute; overflow: visible;`) and let only `#chat-stream` scroll (`flex: 1; overflow-y: auto; overflow-x: hidden;`), ensuring the character's body remains completely static during scrolling ("waktu gilir ke atas atau bawah itu ngga ngikut tubuhnya").
- **The Living Container Appendage Clipping Pitfall**: Applying `overflow: hidden;` to the outer living body container card (`#mumu-living-container`) chops off 3D claymorphic ears, antenna spheres, or crests peeking over the top rim into the background canvas. Always enforce `overflow: visible;` on the parent container and restrict `overflow-y: auto; overflow-x: hidden;` exclusively to the nested chat stream container.
- **Mascot Visor Toast Collision**: Positioning floating system toasts at `top: 70px-80px` on mobile places the notification directly across the mascot's eyes and visor, destroying the illusion of a living character. Anchor floating toasts either above the header or suspended above the bottom input dock (`bottom: ~140px`).
- **Lifeless Flat-Tab Ear Anatomy**: Rendering mascot ears as flat rounded rectangular tabs makes them appear like detached UI stickers rather than cohesive 3D physical parts of the character. Use dual-layer claymorphism with an outer volumetric shell and an inset `::after` conch cavity with subtle inner drop shadow.
- **Detached Floating Ear & Static Appendage Pitfall**: Floating mascot ear pods without structural grounding sockets look disconnected and awkward, especially on mobile. Leaving ears completely static breaks the illusion of a living character. Anchor ears with snug base sockets and equip them with multi-state kinetic rigging (organic idle sway, spontaneous listening twitches, thinking radar sweep, and interactive tap-reaction spring pops).
- **Backend Model Suffix Leakage**: Leaking internal backend provider codenames or model suffixes (e.g. `Mumu bk`) into consumer-facing dock pills and status labels adds unnecessary cognitive friction. Keep user-facing model labels cleanly simplified to the core persona identity (`Mumu`).
- **Unparsed Markdown Tables**: Omitting table parsing from markdown formatters displays raw pipe characters and column markers (`|:---|:---|`), creating visual clutter in technical responses. Always detect and compile pipe blocks into semantic, responsive HTML tables.
- **Duplicate Reset Affordance Clutter**: Stacking duplicate "New Chat" buttons in both the fixed header and an in-stream companion bar wastes vertical screen real estate on mobile and truncates companion status text. Keep the global reset button strictly in the top header.
- **Template Card & Tag Button Clutter Pitfall**: Overfilling empty state canvases with multi-paragraph prompt cards, tag buttons, and complex crafters overwhelms the user and feels unrefined compared to premier LLMs like Claude or ChatGPT. Keep empty states serene and zen with concise copy.
- **Missing Generation Abort (Stop Mode)**: Omitting a stop generation mechanism leaves users helpless when an LLM begins generating verbose unwanted output. Always morph the send button into a high-contrast square stop button (`■`) wired to `AbortController.abort()`.
- **Monolithic Frontend Code Sprawl**: Accumulating unused modal templates, obsolete preset blobs, and duplicate CSS overrides inflates frontend files past 3,000 lines, slowing down DOM parsing and developer iteration. Refactor aggressively to keep components modular, clean, and under 1,500 lines.
- **Unstyled Code Copy Failure**: Rendering code blocks without copy affordance forces users to manually select and drag text on mobile screens. Always provide a distinct code block header with language badge and an animated one-click copy button.
- **The Living Container Negative Headroom Trap ("Terlalu ke Atas")**: Setting container `top: 50px` on mobile directly crushes the container against the top navbar (height 52px), crowding the mascot's head against the screen ceiling and causing unclipped appendages to collide with header dropdowns. Always enforce container `top >= 80px-86px` on mobile (desktop `top >= 76px`) to ensure $\ge 30\text{px}$ of clear open headroom.
- **The Flat Solid Dot Happy Eye Illusion**: Rendering joyful/happy companion eyes as solid oval or rectangular dots fails at mobile scale, looking identical to neutral or alert eyes. Construct upward-curving crescent arches with top/left/right border outlines and neon bloom (`border-top: 3.5px solid #00e5ff; border-left: 2px solid #00e5ff; border-right: 2px solid #00e5ff; border-bottom: none; border-radius: 14px 14px 0 0; background: transparent;`).
- **The Dead Solid Card vs Frosted Morphic Glass Contrast**: Using 100% opaque flat white fills for large container cards deprives the interface of dimensional atmosphere and visual luxury. Use frosted glassmorphism (`backdrop-filter: blur(24px-28px) saturate(200%)`, translucent white fills, specular rim borders) over drifting ambient glow mesh orbs to produce vibrant refractive depth.
- **The Unicode Emoji Slop Pitfall**: Using Unicode emojis (`✨`, `🐴`, `●`, `✦`, `👍`) across titles, buttons, toasts, and headers destroys the premium, high-end Apple iOS aesthetic and makes the UI feel amateurish. Strictly use clean, sharp inline SVG vector glyphs modeled after SF Symbols.
- **The Full-Screen Settings Modal Trap**: Presenting simple settings as a giant full-screen modal breaks chat context and feels clunky on both desktop and mobile. Mount a compact top-right dropdown popover with horizontal sliding submenus (`‹ Kembali`) for nested configuration.
- **Header Model Picker Disconnection**: Placing model and reasoning controls in the distant top navigation bar disconnects them from the prompt input context. Position model and thinking effort pills directly inside the bottom input dock capsule (like ChatGPT).
- **Mobile Virtual Keyboard Occlusion**: Relying solely on `100dvh` or `env(safe-area-inset-bottom)` leaves floating input capsules hidden beneath or floating awkwardly above mobile software keyboards. Always bind `window.visualViewport` `resize` and `scroll` events to dynamically offset `bottom`.
- **Harsh Blur Cutoff Seams**: Abruptly terminating backdrop-filter containers creates jarring horizontal boundary lines. Always feather blur edges using linear opacity gradient masks (`-webkit-mask-image`).
- **Ambiguous Token Count Confusion**: Displaying bare token numbers (e.g. `~76 token`) confuses users into thinking it represents word or sentence counts. Explicitly qualify as API compute tokens with cost estimates (`45 token • Biaya: $0.0001`).
- **The Flat Dark Navy Prompt Bubble Discordance**: Styling user prompt bubbles with flat, heavy dark navy fills on light-mode or pastel gradient canvases creates a gloomy, jarring visual weight that clashes with playful companion aesthetics. Use a harmonious, luminous multi-stop blue gradient (`#3b82f6` $\to$ `#1e40af`) with specular rim lighting and soft colored ambient drop-shadow.
- **Hidden Automation Schedules Trap**: Burying or omitting background cron automation jobs from settings leaves users blind to background system operations. Expose active cron jobs directly inside a dedicated Skedul submenu.
- **Redundant Dropdown Selection Toasts Trap ("Notif Seperti Ini Ngga Perlu Ada")**: Firing floating toast notifications when the user toggles a model or reasoning effort pill in the input dock adds annoying visual clutter because the pill button text already updates directly under their thumb. On mobile, top-center toasts (`top: 64px-75px`) directly collide with and mask the character mascot's face. Reserve toasts strictly for substantive actions that lack immediate inline feedback (e.g. "Pesan tersalin", "Instruksi disimpan"), and pin them safely to extreme perimeters (`top: 14px` or `bottom: 90px`).
- **Code Block Child Inheritance Clutter (`.message-bubble code`)**: Styling inline code broadly using `.message-bubble code` causes `<pre><code>` inside code block wrappers to inherit background color, padding, and borders, rendering ugly light patches behind every line of code. Always scope inline code using child exclusions (`.message-bubble :not(pre) > code`) and explicitly reset `.code-block-wrapper pre code` to `background: transparent !important; border: none !important; padding: 0 !important; color: #0f2b48 !important;`.
- **HTML Entity Collision in Syntax Highlighting**: Running syntax highlighting regex on pre-escaped HTML breaks string matching (quotes become `&quot;` or `&#039;`), while digit regexes (`\b(\d+)\b`) match and corrupt numeric character references like `&#039;` into `&#<span class="tok-number">039</span>;`, and comment regexes matching `#` treat `&#039;` as Python comments. Extract fenced code blocks with placeholders BEFORE general escaping, tokenize syntax with collision-free token delimiters (`___TKN_n_END___`), escape non-token code fragments, and re-inject safely.
- **The Monochromatic Markup Pitfall**: Restricting syntax highlighting regex solely to JS/Python keywords leaves HTML, XML, SVG, and CSS blocks completely unhighlighted as flat, monochromatic text on light backgrounds. Always include regex passes for HTML tags (`<tag`), attributes (`attr=`), attribute values (`"..."`), and doctypes.
- **Nested Syntax Token Recursion Trap**: When string tokens reside inside HTML attribute replacements, running a single replacement pass leaves unexpanded tokens (`___TKN_n_END___`) inside the rendered code. Use a bounded recursive `while (code.includes('___TKN_') && safety < 10)` loop to fully unwrap nested tokens safely.
- **Modal Header Action Crowding on Mobile**: Stacking multiple textual buttons (e.g. "Mobile", "Desktop", "Tab Baru", "Tutup") in a modal header compresses the title and forces vertical line wrapping on narrow viewports ($\le 390\text{px}$). Enforce `white-space: nowrap; text-overflow: ellipsis;` on titles and hide button text spans under mobile media queries to preserve a compact icon-only toolbar.
- **Layout Linter False-Positive on Media Viewers**: Naming image or lightbox containers with substring keywords like `card`, `box`, `panel`, or `tile` triggers layout audit rules (`EMPTY_DECORATIVE_SLOP`) when the container holds only an image element without text. Name media containers semantically (e.g. `.image-viewer-stage`) to avoid false-positive linter failures.
