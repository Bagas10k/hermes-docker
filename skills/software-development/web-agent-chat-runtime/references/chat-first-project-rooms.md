# Chat-first project rooms with native agents

## 1. Fix the product boundary

Clarify whether a group means an app-local project/topic room with agents, synchronized platform conversations, or multiple human participants. Treat those as different products. For this user's workspace, use owner-and-agent rooms with Telegram separate. A topic room need not have a filesystem folder; associate a native Project only for an explicitly selected workspace.

Keep the conversation primary and background activity nearby. Match room/session navigation to the approved composition: a focus-contained sheet can serve mobile while a persistent nonmodal sidebar serves desktop. Keep book/server/legacy task controls as companion tools. Prefer contextual approvals and readable results over forcing users through a dashboard or technical logs.

## 2. Inspect reuse before defining the adapter

Read the installed native UI and handlers plus current official Programmatic Integration documentation. Separate three evidence levels: handler available in source, authenticated transport handshake, and completed agent interaction. Do not label the first two end-to-end chat.

Reuse the native AIAgent runtime; a raw model call loses the tools, skills, memory, approval and delegation lifecycle the user requested. Inspect whether the installed dashboard embeds a terminal rather than message-based chat; reusing its engine does not require exposing its admin/config/shell routes.

Prefer a supported transport with explicit ownership and the smallest required adapter. Prove readiness, ping and client capabilities using disposable state before admitting a real prompt. Capture actual request/event envelopes before freezing decoders; correlation IDs and deltas are not interchangeable with durable message IDs or payload fields. Do not present an untested transport alternative as a validated recipe.

Build the capability matrix from installed handlers and actual web wiring. Separate agent-callable tools, session commands, profile/global administration and device-dependent UI; absence of a management button does not prove the agent lacks its tools. Inspect command catalog, resolution and structured dispatch separately: a slash executor may reject skill commands that require a different dispatch path, and returned directives can mean output, alias, prefill or a new task rather than completed execution. Do not treat catalog categories as certified safety classes: installed dispatch can try quick/plugin handlers before built-ins, so a safe-looking name may execute a shadowing shell handler. Require explicit command/argument policy and verified provenance before dispatch, and fail closed when provenance is ambiguous. Do not retry every native 4018 through another route; that code can mean a quick command already executed and failed or a bundle failed to load, making a generic fallback a duplicate side effect. Route task directives through the authorized idempotent prompt/approval path; never expose arbitrary RPC or global configuration mutation as a shortcut to parity. Distinguish host microphone capture from phone capture, generated audio files from local playback, and agent GUI tools from embedding a desktop—test each pathway instead of declaring whole feature families unsupported.

## 3. Freeze identity and ownership before parallel implementation

Map principal → profile → room/session → stored session → live runtime session. Preserve both session IDs when native create/resume returns them. Check the installed warm and cold resume envelopes separately: an already-live snapshot can omit profile_name and expose the stored key as session_key, while a cold lazy resume reports profile_name. Validate an omitted warm echo only against the exact runtime previously bound by a verified create/resume; an arbitrary runtime ID is not a substitute for profile verification. Read transcript message text from the actual wire field rather than assuming content. Persist the chosen profile at session creation and forbid profile reassignment; creating a different-profile session is not migrating an existing session. Coalesce simultaneous resume requests for one app session, verify native profile identity before adopting its runtime, and forward the server-bound profile on attachment, prompt and control calls. Recreate a zero-history draft only for the protocol's exact session-not-found code and under the same verified profile; matching digits in an error message or catching every resume error can create a second session after an unrelated failure. Return static public errors rather than concatenating native provider/path details. Resolve the launch home from actual runtime options/environment before migrating legacy records, because an omitted profile does not always mean the default root. Require independently verified historical launch provenance before assigning a profile to old unbound rows: matching today's home to today's catalog proves current identity, not the origin of historical sessions. Leave unverifiable rows readable but unresumable, and never overwrite a nonempty binding. Reject unknown/deleted profiles without falling back to another home. Keep the native transcript authoritative; store app-specific metadata and idempotency separately instead of duplicating history by default.

Inspect the installed profile multiplexer before adding processes: a native per-session profile scope can avoid a process-per-profile broker, but it does not prove safe concurrency with an independent messaging gateway writing the same home. Validate the topology in disposable homes and retain unmeasured locking/overhead risks as hypotheses. Discover existing profiles without transcript previews and project an explicit metadata allowlist; upstream roster rows can contain paths, history snippets or other private fields. Apply the public-metadata boundary inside every allowed text field too: removing row.path does not hide a path or provider URL embedded in display_name, description or model. Sanitize recognized credentials/private tags, mask common location shapes before truncation, bound input size, validate boolean types instead of Boolean('false') coercion, and preserve absent metadata as unknown. Test both field exclusion and embedded-value negatives; label this pattern coverage, not universal personal-data detection. Never copy or edit another profile's configuration, skills, memory or credentials merely to populate a selector.

A source tag and cwd/project association are neither ACLs nor filesystem sandboxes. Validate every operation and event subscription against the server mapping. Reject mutating IDs from unrelated rooms or messaging-gateway-owned sessions before forwarding them; a new web process must not finalize an active Telegram session.

Inspect each telemetry source's process and filtering boundary. A REST endpoint reading a module-level subagent dictionary is process-local and may be globally scoped; it cannot establish complete visibility into independent Telegram or terminal processes. Prefer session-scoped roster/control methods that validate owner session, transport and owner record. Show unavailable/unknown for missing telemetry rather than inventing a quiet or completed state.

## 4. Build one real conversation before expanding

Exercise one authorized prompt through the real agent with a tool, then persist/reopen history. Add two rooms and multiple sessions; switch while one runs and hold a response from room A until room B is selected. Confirm the delayed response cannot overwrite B and switching views does not implicitly stop A.

Bind durable prompt deduplication to principal, room, session and payload. JSON-RPC correlation alone is not idempotency. On reconnect, recover state/events/inflight without resubmitting mutations. Include canonical messages, open requests, current partial text and an authoritative sequence watermark in the snapshot; replay only events newer than that watermark, or start from the snapshot without replaying already represented deltas. Test a running snapshot whose partial text is empty followed by its first visible delta: the client may already be marked streaming while no streaming message node exists. Initialize the node when its message ID is absent, not only when the streaming flag is false, or a legitimate post-reconnect answer can disappear. Bind parser cursors to the session and transport epoch and test snapshot-plus-next-delta duplication negatives. On an uncertain restart outcome, update both durable status and cached idempotency response to unknown/not accepted, expose that state in GET and SSE snapshots, and reject a fresh request ID from bypassing the unresolved turn. Settle durable idempotency when the actual native completion arrives; leaving completed turns queued makes every restart falsely uncertain. Query the newest bounded history page in descending order and reverse it for display, rather than returning the first page forever.

Probe the installed transport before negotiating client capabilities: some stdio dispatchers support server requests directly but reject `client.capabilities` with -32601. Use the supported `gateway.capabilities` probe and inspect actual request frames instead of copying a WebSocket-only handshake. Restore open_requests, answer the exact request ID with supported native values and clear only the prompt identified by request.cancel. Require a real approval to unblock a real pending operation; a visible approval card is not evidence of that behavior.

Treat `message.complete` as the end of a native turn, not proof that all asynchronous child work completed. Prove one real tool-and-approval turn first, then test delegation separately through its eventual child result; preserve failed/timeout evidence and never convert an interim “waiting for child” response into task success. Decode the installed event envelope exactly: token text may be `params.payload.text`, and session snapshots may carry status/open_requests at the top level rather than inside payload.

Keep delegated patches small enough to save early. After a paginated-read overwrite refusal, patch a unique function or complete the missing read before retrying; a timeout with an unsaved rewrite leaves the old implementation unchanged. Do not treat authored tests or a stale source-bound PASS as evidence that the new controller landed.

Wire Stop to the native turn/session interrupt and verify its effect. Aborting a browser fetch only disconnects the consumer unless the server explicitly propagates cancellation.

Before exposing richer progress text, probe the visible-output boundary through the real event handler using synthetic canaries. Rejecting reasoning event names or stripping complete tags in each chunk is insufficient: split opening/closing tags, unfinished private blocks and credential-shaped spans can cross delta boundaries, then survive in accumulators or reconnect snapshots. Keep these probes isolated from production sessions, assert both ordinary visible-text delivery and canary absence, and label a reproduced failure as RED rather than claiming a repair. Verify deltas, interim/final aliases, progress summaries and snapshot/replay separately; final sanitization cannot retract text already emitted. Keep unresolved raw token/tag state before replacing secret-shaped spans: redacting a partial token and then retaining the replacement loses the continuation state and can release its suffix on the next chunk. Bound retained state, suppress private bodies without storing them, and test every two-chunk cut plus one-character delivery, quoted values, nested/unclosed tags and oversized inputs. Pair canary absence with byte-preserved ordinary text and pre-completion streaming of safe words. Drop unreviewed rendered/verbose or nested metadata channels rather than relying on text regexes to infer which channel was public.

Project progress fields from the installed event schema rather than forwarding arbitrary arguments/results. Preserve nested usage envelopes and treat final usage as authoritative where the protocol says so. Inspect the installed Usage field names instead of inventing normalized prompt_tokens/cache fields: an upstream tick can be payload.usage with prompt/completion/total/cache_read/cache_write. Retain absent metrics as unknown, do not add cumulative ticks together, and distinguish a tool-complete notification from a proven successful tool result or whole-task completion. Label adapter-observed start/end times as observations; do not imply they measure native execution duration or complete task success. Validate finiteness after unit conversion and subtraction, not just on input values, because finite seconds can overflow when multiplied into milliseconds. Apply identifier syntax and recognized-secret checks to ID/tool fields as well as summaries. Drop unknown task states and missing revisions rather than inventing pending/zero; stale or fabricated revisions can overwrite authoritative reconnect state. Restore bounded per-turn activity with the same sequence watermark as text so reconnect does not duplicate steps or leak a prior session's work.

## 5. Add visual output and attachments without changing authority

Render ordinary text/code through safe DOM APIs; generated HTML/SVG must not execute in the authenticated document. Use an opaque-origin sandbox without allow-same-origin, deliberate CSP and restricted parent messaging/network capabilities. Check inherited CSP before choosing srcdoc; do not globally weaken the app policy merely to make a preview run. For authenticated form POST into an opaque-origin iframe, reproduce the parent's Referrer-Policy too: Chromium can send Origin null under `no-referrer`, causing a legitimate exact-Origin guard to return 403. A parent `same-origin` referrer policy can preserve the exact same-origin POST while suppressing cross-origin referrers; verify with the actual router and browser instead of allowing Origin null or bypassing CSRF. Keep the isolated preview response itself no-referrer. Prove actual visual behavior and failed privileged access in the browser.

Test navigation to companion tools in a cookie-blocked WebView: a new page cannot inherit a bearer held only in another page's memory. Do not solve that gap with tokens in URLs, persistent browser storage or weakened proof replay checks. Keep authentication continuity an explicit integration gate until a tested supported mechanism exists.

For attachment storage:
1. Derive principal/room on the server and issue opaque attachment IDs; never accept a client filesystem path.
2. Bound encoded and decoded size, validate canonical base64, filename, MIME/extension and content signatures. Reject unsupported active formats.
3. Store outside public/executable roots with private directory/file modes. Verify canonical containment, symlinks and file descriptors; path.resolve alone is not a jail.
4. Read by owner/room/attachment identity, recheck size/hash and return metadata without private paths. Only an authorized server caller may hand a verified path to the agent.
5. Test wrong owner/room, malformed IDs, traversal, replaced symlinks, oversized payloads and mismatched content alongside a valid upload/read. MIME magic checks are not malware scanning or full document validation.

## 6. Verify each claim at its actual boundary

Require real tools, delegation with traceable parent/child relationships, native approvals, two-room isolation, replay safety, foreign-session rejection and sandbox escape negatives. Preserve raw output, exit status and implementation/test hashes. A PASS with an unresolved authorization or stale-data defect is a rejection until fixed and rerun independently.

Keep component tests, integrated agent behavior, public anonymous/authenticated routes and physical Telegram acceptance separate. Passing the legacy app suite protects that app; it does not complete new chat features. Publish only the candidate bound to the final verdict, read back exact served assets, and provide mobile/desktop screenshots with a short visual report. Use neutral synthetic identities throughout fixtures and evidence.

## 7. Restructure an existing chat surface without weakening it

1. Inspect the incumbent HTML, dynamic DOM builders, CSS and screenshots before proposing changes. Trace generated class names into styles: a present upload feature can still render an unstyled remove button because its dynamic classes have no matching CSS. Confirm whether the user wants layout/flow restructuring or visual refinement, then record the selected composition and preserved functions before parallel edits.
2. Snapshot the live frontend and immutable backend into a separate candidate. Give shell and controller writers disjoint files with a shared DOM contract; enumerate actual IDs from the current HTML rather than treating a manually selected critical subset as the complete inventory. Keep the earlier release candidate intact.
3. Inspect each reused test's source-root constant before running it. A configurable top-level runner does not retarget child suites with hardcoded paths. Parameterize the harness or make an isolated copy with the same behavioral assertions and separate output paths; do not overwrite the previous candidate to make old paths work. Update navigation steps when approved controls move into a menu, not the underlying security or task assertions.
4. Use bounded, observable acceptance criteria. Give mobile titles useful width, clear hierarchy and access to the full name; arbitrary-length titles cannot all fit without truncation. Bound the desktop composer to the reading column and measure before/after geometry if claiming an improvement. Never promise an ergonomic percentage from a guessed baseline.
5. Exercise readiness and draft transitions: no room, room without a session, loading, ready, running, uncertain and expired. Match Send/upload affordances to the authorized state, preserve drafts when switching, and keep create/select explicit. Styling an active control cannot repair an admission dead end.
6. Test responsive navigation and keyboard behavior in a browser: desktop sidebar remains nonmodal; mobile sheet closes and restores logical focus; resizing never leaves the page inert. Treat missing explicit focus calls as hypotheses, because native dialog behavior may already manage focus. Verify actual focus, backdrop, IME and keyboard-viewport transitions instead of certifying them from static inspection.
7. Review populated conversation, attachment/quote draft, pending permission, visual preview and empty state at mobile/desktop sizes. Keep touch controls at the agreed minimum, code horizontally readable and low-frequency utilities discoverable. Distinguish proposed requirements from passed checks; an audit document or a screenshot of one empty state is not final UX acceptance.
