# Task-surface contract
Record target, requested surface/route, source kind and completion criteria before a UI change. Inspect existing flow. For prototype build–review–test requests, separate (a) local development loop, (b) browser-accessible test surface, and (c) later production deployment; do not silently promote the task into a gateway/VPS rollout. Before adding infrastructure or multiple environments, first check whether the existing app and route already provide the shortest usable browser path. A build, test pass, or login HTTP 200 is not completion when the user asked to use the app: verify the exact user-facing route and core interaction. If the only viable route change touches shared services, state that concrete impact and ask once immediately; continue independent code/test work without repeatedly replanning. Do not replace main route with test route or URL input with local upload. Map the public hostname to its actual gateway and upstream before selecting a deployment folder; a local static route on another service does not establish the public route. Avoid recursive root filesystem searches (`find /home/ubuntu`, broad `grep -r`) when resolving ambiguous project names or user denials ("bukan di folder X"). Often a standalone user-facing app/route is physically hosted under an umbrella service directory whose folder name differs from the product brand in the user's mental model. When target ambiguity arises, check active reverse proxy/PM2 route mappings or ask for the exact public URL/path directly; never launch unbounded filesystem scans that exhaust tool iteration budgets. For a public, self-contained artifact behind a default-private gateway, allow only the exact reviewed GET/HEAD paths and serve the existing source file; preserve sibling/private routes and verify negative access checks. Test the exact route in a browser; attach non-sensitive evidence. For generated deliverables, attach/link the exact produced artifact (and verify its path); keep source/repository URLs separate, never substitute a source URL for the requested output file. Run `/home/ubuntu/agent-quality/quality_gate.py <record.json>` before reporting completion.
