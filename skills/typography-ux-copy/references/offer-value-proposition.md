## 1. UX copy versus product copy

UX copy helps users operate the product.
Product/marketing copy helps users understand why the product is valuable.

Do not use marketing language inside every operational control. A settings page should usually be direct, not promotional.

## 2. Value proposition architecture

A strong hero or product description typically combines:
- audience or context
- desired outcome
- differentiator or mechanism
- credible evidence if available
- clear next step

Template for reasoning, not literal final copy:
`For [audience], achieve [outcome] with [mechanism/differentiator], without [meaningful friction when true].`

Avoid stuffing every field into one sentence.

## 3. Benefit hierarchy

Translate features into user value:

Feature -> Capability -> Practical outcome -> User benefit

Example:
Feature: automatic version history
Capability: restores previous states
Outcome: recover accidental changes
Benefit: work with less fear of losing progress

Use the layer appropriate to the surface. Technical audiences may need capability detail; executive buyers may care more about outcome and risk.

## 4. Feature descriptions

A feature card should not repeat the heading in longer form.

Weak:
Heading: "Real-time analytics"
Body: "Get real-time analytics that provide analytics in real time."

Better:
Heading: "Live performance view"
Body: "See traffic, conversions, and anomalies as new events arrive."

Do not claim "real time" unless the underlying product actually meets the intended latency expectation.

## 5. Offers and pricing

Offer copy should make the commercial terms understandable:
- price
- billing period
- trial duration
- cancellation terms
- usage limits
- included features
- renewal behavior

Do not hide material conditions in low-emphasis copy.

Avoid false scarcity and false urgency.

## 6. CTA strategy

Match CTA to commitment level.

Low commitment:
- View demo
- Explore templates
- Compare plans

Medium:
- Create account
- Start free trial

High commitment:
- Buy now
- Upgrade plan
- Confirm purchase

Do not label a paid commitment "Continue" when a clearer outcome label is possible.

## 7. Trust and proof

Use proof only when supplied or verifiable:
- customer quote
- case study
- benchmark
- certification
- review count
- uptime metric

Never fabricate proof to improve copy.

## 8. Ethical persuasion

Do not use:
- confirmshaming
- hidden opt-outs
- forced continuity language that conceals renewal
- guilt-based permission prompts
- deceptive button hierarchy
- invented countdowns
- fabricated social proof

Persuasion should make value clearer, not reduce user agency.
