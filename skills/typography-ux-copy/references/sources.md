# Sources and Update Notes

This skill synthesizes current platform guidance, accessibility standards, and established content-design practice. Re-check sources when platform guidance changes.

## Primary sources

### Apple Human Interface Guidelines - Typography
https://developer.apple.com/design/human-interface-guidelines/typography

Key current guidance used:
- typography conveys hierarchy and must remain legible
- avoid excessively light weights for important small text
- minimize typeface count
- support Dynamic Type and larger accessibility sizes
- custom fonts must preserve accessibility behavior

Apple's typography page includes changes through December 2025 and remains current in 2026.

### Apple Human Interface Guidelines - Writing
https://developer.apple.com/design/human-interface-guidelines/writing

Key guidance used:
- interface words are part of user experience
- determine a consistent product voice
- use consistent terminology and flow labels
- write through the lens of language, not as an afterthought

### Apple Human Interface Guidelines - Design Principles
https://developer.apple.com/design/human-interface-guidelines/design-principles

Current 2026 guidance emphasizes purpose, agency, flexibility, simplicity, craft, and delight. This skill uses the principles of clarity, hierarchy, concise language, and deliberate wording.

### Apple Human Interface Guidelines - Branding
https://developer.apple.com/design/human-interface-guidelines/branding

Current 2026 guidance reinforces brand voice while keeping content and familiar platform behavior primary.

### W3C WCAG 2.2 - Text Spacing
https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html

Key requirement used:
Content must not lose information or functionality when users override text spacing to specified values for line height, paragraph spacing, letter spacing, and word spacing.

### GOV.UK Service Manual - Writing for user interfaces
https://www.gov.uk/service-manual/design/writing-for-user-interfaces

Key practices used:
- minimize cognitive load
- keep UI copy short and direct
- put important words first
- use user language
- improve the interface before adding explanatory text

### GOV.UK Design System - Error message
https://design-system.service.gov.uk/components/error-message/

Key practices used:
- explain what is wrong and how to fix it
- keep entered information after validation errors
- use specific messages
- avoid blame, jargon, generic errors, and unhelpful humor

### GOV.UK Service Manual - Designing good questions
https://www.gov.uk/service-manual/design/designing-good-questions

This guidance was updated June 24, 2026 and is used for form questions, help text, and error prevention.

## Secondary sources

### Microsoft Learn - Buttons
https://learn.microsoft.com/windows/apps/develop/ui/controls/buttons

Used for general reinforcement that button text should be concise, specific, and action-oriented while accounting for localization expansion.

### Apple WWDC - Writing for interfaces
https://developer.apple.com/videos/play/wwdc2022/10037/

Used for the content-design framing that UX writing designs the experience through language.

## Maintenance rule

When this skill is updated:
1. Re-check Apple HIG change logs.
2. Re-check WCAG/WAI guidance.
3. Re-check the GOV.UK Design System for updated error/form research.
4. Treat old platform-specific examples as principles only if the platform has materially changed.
5. Prefer current official guidance over blog summaries.
