# Chat UI reference and acceptance

- Separate the UI inside a reference device from the presentation poster; transfer palette roles, hierarchy and component grammar, not device chrome, editorial notes, example identities, or unrelated domain features.
- Treat a later user-pinned theme as replacing earlier inferred tokens. Update the surface contract and steer active single-file owners immediately; keep settled composition and product capabilities unless the user also changes them.
- Put dark lettering on a bright gold primary action and measure contrast. Check computed styles, not token presence: a later neutral icon-button selector can erase the primary fill despite correct palette variables.
- Preserve all existing DOM IDs when restructuring a mature vanilla-JS UI. Retain a scoped new candidate, leave prior evidence untouched, and refuse backend or live drift before frontend-only promotion.
- Make persistent desktop navigation nonmodal and mobile navigation modal through one shared lifecycle helper. Test the actual :modal state, focus and hit testing; absence of an inert attribute alone does not prove the page is usable.
- Clear obsolete session rows and draft presentation immediately when switching rooms, before awaiting the next room response. Keep the old draft in its per-session store; stale actionable rows can otherwise select the wrong session even with response guards.
- Count prompt requests at the real application route and native wire seam. A defaultPrevented flag, retained textarea value, or a monitor watching a nonexistent /prompt route is not proof that Enter did or did not submit.
- Isolate keyboard checks from a prior upload scenario. Remove staged attachments through the UI before testing text-only dispatch; otherwise a missing fixture attachment RPC can masquerade as a keyboard failure.
- Simulate visualViewport height reduction explicitly and label it simulation. Dispatching resize at the unchanged height proves no keyboard handling and must not authorize physical WebKit claims.
- Treat native dialog focus behavior as a browser observation, not a source-code assumption. Native focus restoration may already work; backdrop dismissal is a separate property.
- Wait for the exact target room response and iframe navigation rather than an arbitrary sessions response or immediate page.frames lookup. Test synchronization bugs must not be patched into production behavior.
- Bound flex/grid chat shells with min-height:0 and nonshrinking message items. Assert composer coordinates and inspect both transcript-top and transcript-bottom captures; a partial message at a scrolled boundary is not automatically a clipped layout.
- Bind functional and visual approvals to the same source hashes. A static asset route that reads disk with no-store may need no process restart; prove the exact deployed bytes by local/public readback instead of restarting an unrelated gateway.
- Keep deterministic browser evidence distinct from real model, transport and physical Telegram/WebView acceptance. Publish unresolved reviewer advisories without inflating a ship disposition into a claim of perfection.
